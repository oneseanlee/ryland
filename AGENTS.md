# Architecture rules
- Unpaid inquiry cleanup uses an owner/admin-checked RPC with payment protection and audit history; cancelled orders leave active lists while documents and invoice records remain intact.
- Inquiry reads use session-scoped React Query keys; database row policies remain the authority for access, allowing reads to start without waiting for an affiliate profile.
- Admin inquiry documents load per opened order, and cached inquiry lists stay visible during refreshes to avoid blocking navigation on unrelated data.
- Inquiry accounts without affiliate profiles use a bounded loading fallback; admins navigate to the guarded admin inquiry route rather than waiting for a partner record they do not need.
- Inquiry submission delivery runs in a separate authenticated function after checkout via EdgeRuntime.waitUntil; per-order checkpoints and leases support admin retries without repeating completed steps or blocking payment navigation.
- Inquiry document copies go to the GoHighLevel contact file field via the documented upload-custom-files endpoint (user accepted that GHL file links open without sign-in); originals stay in private storage. The shared helper sends the owner's full set in one request when new files exist and verifies the contact's file count before marking new rows, because uploads replace the field. Post-submission attachments use push-lead-documents; undelivered inquiries defer to delivery.
- Late inquiry document pushes run through a drain loop: pushes per inquiry order are serialised by the inquiry_lead_delivery.locked_until lease (only while state is complete; the stored value is the holder token) with release-then-recheck; every successful round sends all of the order's pending supported rows. A caller answered 'queued' retries from the browser at about +30 s, +90 s and lease + 30 s (derived from INQUIRY_PUSH_LEASE_MS); if all fail it shows a calm 'saved, will be sent shortly' message and the last try records the waiting error on the rows. A row can still wait if the uploader closes the page before the retries and the lease holder crashed, until the next upload or an admin retry. A lease-release error is logged and never skips the Slack reply / Mission Control re-add; the lease TTL frees the lock. Each successful round's newly-added count drives a best-effort Slack thread reply on the saved initial timestamp, so Slack failures never fail a verified upload. Each such round then makes one best-effort re-enrollment of the contact in the GHL Mission Control workflow (late inquiry pushes only, never initial delivery or affiliate leads; failures land in last_error without failing the push). Affiliate-lead pushes are not serialised. File type/size rules live in one pure shared module used by both the app and the functions.
- Fundability Score scoring/content lives in one pure shared module (supabase/functions/_shared/fundability.ts) used by the app and the submit function, which recomputes scores server-side; see docs/fundability-score.md.
